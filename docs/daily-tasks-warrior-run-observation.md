## 二、根因：副本免费次数被同角色提前耗尽

### 关键机制（已用对照实验证实）

**「免费次数」= 每个副本每天 1 次，按角色独立，与难度档位无关。**

单变量对照（以 warrior 角色打开，2026-09-18 11:00–11:25 逐个实测）：

|---|---|---|---|---|

| 腐化沼泽、毒蛇神庙、地精岛 | 风暴群岛 | **mage/rogue** 06:2x–06:35 全都打过 | **全都有 `免费(1/1)`** | — |

**只有 warrior 自己动过的那个区域没免费，别的角色打过的区域全都有** —— 单一变量，指向明确：

1. **mage / rogue 打掉的免费，warrior 照常能用** → 免费次数按**角色**独立，不是账号共享
2. **唯一没免费的是「亡灵之地」整片** → 该角色今天动过这个区域
3. 另外实测：把「永恒王座」从史诗切到**普通**，仍无免费 → 免费次数**跨难度共用**，与档位无关

## 三、放大的代码缺陷：失败被写成成功

`auto_dungeon_core.py:145-149`：

```python
if not battle_started:
    logger.warning("⚠️ 无免费按钮，标记为已完成")
    db.mark_dungeon_completed(zone_name, dungeon_name)   # ← 假完成
```

**「没有免费次数」被当成「今日已完成」写进数据库。** 后果：

1. 数据库显示完成，游戏里其实一次都没打 —— 进度统计失真
2. `run_dungeons.py` 判定超预期完成，掩盖了真实的免费次数耗尽
3. 与上一轮发现的 `total_selected` 口径 bug（把「日常任务」11 项当副本数）叠加，warrior 每天恒判未完成 → 触发 3 轮重试、每轮重跑全部配置
